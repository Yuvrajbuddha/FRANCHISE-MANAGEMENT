# Database Architecture & Models

## Technology Stack
- **Database Engine**: PostgreSQL
- **ORM / Query Builder**: Drizzle ORM (`drizzle-orm/node-postgres`) & Prisma Client
- **Migration & Schema Tools**: Drizzle Kit & Prisma

## Schema & Tables

### 1. `companies`
- Master organization entity (e.g., `Aura Foods QSR Network`).
- Fields: `id`, `name`, `industry`, `subscriptionTier`, `createdAt`.

### 2. `users`
- System actors with role-based access control (RBAC).
- Fields: `id`, `companyId`, `name`, `email`, `role` (`ADMIN` | `OWNER` | `FRANCHISE` | `OFFICER`), `assignedOutletId`, `assignedOutletName`.

### 3. `outlets`
- Store operational locations.
- Fields: `id`, `outletId` (e.g. `OUT-042`), `name`, `city`, `state`, `operatingModel` (`FOCO` | `COCO`), `status`, `manager`, `complianceScore`, `riskScore`.

### 4. `outlet_sales`
- Daily aggregated sales, transactions, gross revenue, food cost, royalty calculation, and peak hour telemetry.

### 5. `outlet_inventory` & `inventory_reconciliations`
- Theoretical vs. physical counts, variance percentage, variance cost, and reconciliation status (`VERIFIED` | `MISMATCH_FLAGGED`).

### 6. `compliance_inspections` & `cctv_evidence_verifications`
- Quality officer evaluations, CCTV surveillance submissions, extracted frames, timestamps, and compliance rating (`1-10`).

### 7. `outlet_alerts`
- High, Medium, and Critical operational alerts generated by deterministic engines for SLA tracking.

### 8. `outlet_corrective_actions` (CAPA)
- Corrective and Preventive Action logs with root cause analysis, preventive steps, assigned owner, and status progression (`OPEN` -> `IN_PROGRESS` -> `RESOLVED` -> `VERIFIED`).
